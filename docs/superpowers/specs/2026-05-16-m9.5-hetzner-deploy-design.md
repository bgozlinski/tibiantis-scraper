## §1 Cel + scope

Po M9 mamy deployable artifact (pre-built Docker image w registry) i `docker-compose.yml` z 7 services + migrate one-shot. **Brak realnego deploy'u** — nikt nie uruchomił tego stack'a na production VM. M9.5 zamyka pętlę "działa w prod": aplikacja Tibiantis Monitor chodzi na realnej Hetzner VM (CX22 Falkenstein), Discord bot odbiera commands z dev guild, Celery beat scrapuje co X minut, `/health/` odpowiada 200 via SSH tunnel. Operator (Ty) ma dokumentowany runbook żeby powtórzyć deploy (lub rebuild VM) za miesiąc bez session-context.

Plus M9.5 robi **registry swap ghcr.io → Docker Hub**: aktualnie M9 deployable artifact jest w `ghcr.io/bgozlinski/tibiantis-scraper:master`, ale user preferuje Docker Hub (anonymous pull z VM bez `docker login`, industry standard, prostszy auth flow).

### W zakresie M9.5:
- **D45 Registry swap:** `.github/workflows/docker.yml` push do `docker.io/bgozlinski/tibiantis-scraper` (public repo, anonymous pull). `docker-compose.yml` 5× `image:` swap. GitHub Secrets `DOCKERHUB_USERNAME` + `DOCKERHUB_TOKEN` (scoped PAT). Cleanup ghcr.io versions.
- **D46 VM provisioning + hardening:** Manual Hetzner Cloud Console setup (CX22 Falkenstein, Ubuntu 24.04, SSH key, Hetzner Cloud Firewall). `docs/scripts/bootstrap.sh` (deploy user + sudo + SSH hardening + UFW + Docker install). `docs/deploy-runbook.md` sections 1-3.
- **D47 First deploy + monitoring:** Dorzucenie `uptime-kuma` jako 9. service w `docker-compose.yml` (port 3001 lokalny, SSH tunnel access). First manual deploy na VM (`docker compose pull && up -d`). 4 Kuma monitors (web /health/, postgres/redis/mongo TCP). Discord bot live test w dev guild. `docs/deploy-runbook.md` sections 4-10.
- **D48 Closure:** `docs/dev-runbook.md` carry-over consolidation z M3-M9 (Windows gotchas, MSYS path, `docker compose build` race fix, Compose `$VAR` interpolation, `pre-commit clean` workflow, Celery `-P solo`). PROGRESS.md M9.5 retro section + milestone close.

### Poza zakresem M9.5 (M-future / osobne milestones):
- **DNS + TLS** — subdomain → Hetzner IP, Caddy/Traefik reverse proxy, Let's Encrypt automation. Aktualnie SSH tunnel access (`ssh -L 8000:localhost:8000 -L 3001:localhost:3001 deploy@<ip>`).
- **Static files w prod** — `collectstatic` + WhiteNoise / Caddy. Django admin nieosiągalny w M9.5 (chyba że przez SSH tunnel + akceptujesz broken CSS).
- **CI deploy automation** — GHA SSH job po master merge (`docker compose pull && up -d` na VM). Manual `ssh + docker compose pull/up` w M9.5.
- **Backups** — postgres dump → Backblaze B2 / Hetzner Object Storage. Kandydat M-future.
- **Advanced monitoring** — Grafana + Prometheus / Netdata. Kuma wystarcza w M9.5.
- **VM-level logs aggregation** — Loki + Promtail. Mongo `app_logs` (z M6) już mamy via `docker logs <service>` na żądanie.
- **Multi-environment** — staging + prod. Single VM prod-only w M9.5.
- **fail2ban / unattended-upgrades** — M-future hardening polish (M10 kandydat lub osobny "VM hardening polish").
- **Discord bot Mongo heartbeat + Kuma monitor #5** — wymaga app code change (M-future).
- **Static IPv4 reservation** — Hetzner public IP jest ephemeral przy server delete; M-future jeśli DNS A record stabilność wymagana.

## §3 Decyzje designowe (zaakceptowane 2026-05-16)

### §3.1 Registry swap ghcr.io → Docker Hub (D45)

**Workflow `.github/workflows/docker.yml` changes:**

```yaml
jobs:
  build:
    permissions:
      contents: read
      # packages: write   ← USUNIĘTE (Docker Hub używa secrets, NIE GITHUB_TOKEN)

    steps:
      - uses: docker/login-action@v3
        if: github.event_name != 'pull_request'
        with:
          # registry: ghcr.io   ← USUNIĘTE (Docker Hub default registry)
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - uses: docker/metadata-action@v5
        with:
          images: bgozlinski/tibiantis-scraper   # ← BEZ "ghcr.io/" prefix
          # tags pattern bez zmian (branch/semver/sha-short)
```

**Compose `docker-compose.yml`** — 5× `image: bgozlinski/tibiantis-scraper:master` (zamiast `ghcr.io/bgozlinski/tibiantis-scraper:master`).

**GitHub Secrets (manual pre-PR):**
- `DOCKERHUB_USERNAME=bgozlinski`
- `DOCKERHUB_TOKEN=<PAT>` z scope **Read + Write + Delete** dla `bgozlinski/tibiantis-scraper` only (NIE account-wide PAT — least privilege per Docker Hub access token UI)

**Cleanup ghcr.io (post-merge):** `gh api -X DELETE user/packages/container/tibiantis-scraper` — nuke whole package + all versions.

**Trade-offs vs ghcr.io:**

| Aspekt | ghcr.io (M9) | Docker Hub (M9.5) |
|---|---|---|
| Auth on push | `GITHUB_TOKEN` auto-scoped | PAT w GitHub Secrets (manual setup) |
| Auth on pull | PAT z `read:packages` lub `docker login ghcr.io` | **Anonymous pull (public repo)** |
| Setup overhead | Zero (GITHUB_TOKEN auto) | ~5 min (PAT + 2 secrets) |
| Pull rate limit | None (GitHub generous) | 100/6h anonymous, 200/6h authenticated (single VM OK) |
| Industry familiarity | GitHub-specific | Standard (canonical Docker registry) |
| Public repo cost | Free | Free |
| Mirror potential | N/A | M-future: pull przez gtm proxies / cache layers easier |

**Decyzja swap, nie mirror** — single source of truth, prostszy workflow, mniej moving parts.

### §3.2 Hetzner VM provisioning manual via Cloud Console (D46)

**Konfiguracja (console.hetzner.cloud → Projects → tibiantis-monitor):**

| Setting | Value | Rationale |
|---|---|---|
| Location | Falkenstein DE-FSN | ~30ms z PL, najbliższy datacenter |
| Image | Ubuntu 24.04 LTS | Long-term support (until 2029), recent Docker compatibility |
| Type | **CX22** (2 vCPU shared, 4GB RAM, 40GB SSD, 20TB traffic) | ~6€/mc. Idle stack ~1.5-2GB RAM (8 services), margines pod load. CPX11 z 2GB RAM byłby na granicy. |
| Networking | Public IPv4 + IPv6 (default) | IPv4 dla simplicity (Docker Compose default), IPv6 free dodatek |
| SSH Keys | Upload local `~/.ssh/id_ed25519.pub` | Key auth from day 1 |
| Firewall | New "tibiantis-firewall" | UI-managed second layer ponad UFW |
| Cloud Config | None | Manual bootstrap w SSH session (learning focus) |
| Volumes | None (40GB SSD inline) | Postgres + Mongo data tu mieszczą się na years; M-future wydzielony volume gdy rośnie |
| Backups | Disabled | +20% miesięcznie (~1.2€). M-future: postgres dump → object storage cheaper + portable |
| Labels | `env=prod`, `project=tibiantis` | Inventory tagging dla M-future multi-server |

**Hetzner Cloud Firewall rules (UI):**
- Inbound TCP 22 from `<your-current-IPv4>/32` (sprawdzić IP via https://api.ipify.org)
- Inbound ICMP from `0.0.0.0/0` (ping/traceroute debug)
- (Brak inbound 8000/3001 — SSH tunnel only)
- Outbound: allow all (Docker pulls, package updates, Discord gateway)

**Bezpieczeństwo "0.0.0.0/0" dla SSH 22?** Świadomie ograniczone do `<your-IPv4>/32` w spec'u, ale jeśli operator ma dynamic ISP IP, fallback 0.0.0.0/0 + fail2ban (M-future). M9.5 zakłada static lub semi-static home IP.

### §3.3 Hardening minimal must-haves (D46 `bootstrap.sh`)

```bash
#!/bin/bash
set -euo pipefail

# 1. Create deploy user
useradd -m -s /bin/bash -G sudo deploy
mkdir -p /home/deploy/.ssh
cp /root/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys

# 2. Sudo bez hasła (single operator + key-only SSH = OK; M-future ograniczyć do docker)
echo "deploy ALL=(ALL) NOPASSWD:ALL" > /etc/sudoers.d/deploy
chmod 440 /etc/sudoers.d/deploy

# 3. SSH hardening
sed -i 's/^#*PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sed -i 's/^#*PermitRootLogin.*/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config
sed -i 's/^#*ChallengeResponseAuthentication.*/ChallengeResponseAuthentication no/' /etc/ssh/sshd_config
systemctl reload sshd

# 4. UFW (layer 2 ponad Hetzner Cloud Firewall — defense-in-depth)
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp comment 'SSH'
ufw --force enable

# 5. Docker install (official script — convenience > apt-get docker.io which lags versions)
curl -fsSL https://get.docker.com | sh
usermod -aG docker deploy
systemctl enable --now docker

# 6. apt updates baseline
apt-get update
apt-get upgrade -y
apt-get autoremove -y

echo "Bootstrap complete. SSH as deploy@<ip> from now on."
```

**Świadome decyzje:**
- **`PermitRootLogin prohibit-password`** zamiast `no` — pozwala root via SSH key (recovery scenario), ale nie password. Standard practice.
- **`NOPASSWD:ALL` dla `deploy`** — single-operator MVP, OK trade-off. M-future: ograniczyć do `docker compose *` przez sudoers rule.
- **8000/3001 NIE open na UFW** — wymusza SSH tunnel access. M-future + Caddy odwraca (Caddy słucha 443, internal routing).
- **fail2ban/unattended-upgrades skip M9.5** — minimal MVP. M-future kandydat w M10 Hardening lub osobny "VM hardening polish" milestone.

### §3.4 First deploy flow (D47)

```bash

sudo chown deploy:deploy /opt/tibiantis
cd /opt/tibiantis

# Tylko 2 pliki — NIE full git clone (source code jest w image):

docker compose exec web curl -fsS http://localhost:8000/health/
```

### §3.5 Uptime Kuma 9. service (D47)

**Dodanie do `docker-compose.yml`:**

```yaml
  uptime-kuma:
    image: louislam/uptime-kuma:1
    volumes:
      - uptime_kuma_data:/app/data
    ports:
      - "127.0.0.1:3001:3001"   # localhost-only bind → tylko SSH tunnel access
    restart: unless-stopped
    # No healthcheck — Kuma monitors innych, nie sama siebie

volumes:
  postgres_data:
  mongo_data:
  uptime_kuma_data:    # NEW
```

**`127.0.0.1:3001:3001` (NIE `3001:3001`)** — bind na loopback, nie public interface. Defense-in-depth: nawet jeśli UFW/Hetzner Firewall fail, Kuma UI NIE jest reachable z internetu.

**Konfiguracja przez UI (post-deploy, manual):**
- Open `http://localhost:3001` via SSH tunnel
- Setup admin user + password (zapisz w password manager)
- Add 4 monitors:
  1. **web /health/** — HTTP(s), URL `http://web:8000/health/` (Docker internal DNS), interval 60s, status code 200
  2. **postgres** — TCP Port, Hostname `postgres`, Port 5432, interval 60s
  3. **redis** — TCP Port, Hostname `redis`, Port 6379, interval 60s
  4. **mongo** — TCP Port, Hostname `mongo`, Port 27017, interval 60s

**Trade-off:** Kuma dorzuca ~150MB RAM (free tier image z SQLite). Mała ofiara na 4GB VM (~3.7% RAM). UI exposed tylko via SSH tunnel — bezpieczne.

**Skip w M9.5:** discord_bot Kuma monitor — wymaga app code change (Mongo heartbeat write co 60s, custom Kuma monitor type). M-future.

## §5 Error handling

### §5.1 D45 — Docker Hub auth failure

| Failure | Detection | Recovery |
|---|---|---|
| PAT expired / wrong scope | Workflow log "Login Failed" | Regenerate PAT z Read+Write+Delete scope dla `bgozlinski/tibiantis-scraper`, `gh secret set DOCKERHUB_TOKEN` |
| Secret missing | Workflow log "Username and password required" | `gh secret list` confirm + re-set |
| Rate limit (push) | Docker Hub 429 | Authenticated push limit jest hojny (1000/6h), nie powinno trafić w M9.5 |
| Image name collision | `bgozlinski/tibiantis-scraper` ktoś inny ma | Free name lub change to `bgozlinski-tib/tibiantis-scraper` (verified available przez Docker Hub UI) |

### §5.2 D46 — VM provisioning issues

| Failure | Detection | Recovery |
|---|---|---|
| Hetzner account no payment method | UI refuse server create | Add credit card / IBAN w billing settings |
| SSH key not uploaded before server create | `ssh root@<ip>` password prompt (Hetzner emails initial root password) | Login z email password, upload SSH key + edit sshd_config manual, or destroy & recreate |
| `bootstrap.sh` syntax error | `bash /tmp/bootstrap.sh` exit non-zero | Fix locally, `scp` ponownie, re-execute (idempotent: `useradd` fail jeśli user istnieje — `set -e` exit) |
| UFW lockout (operator runs `ufw deny` before `ufw allow 22`) | SSH session drops, can't reconnect | Hetzner Cloud Console → server → Console (web TTY) → `ufw allow 22/tcp + ufw reload` |
| Docker install fails (apt mirror) | `get.docker.com` script exit non-zero | Retry, lub `apt-get install docker.io docker-compose-plugin` fallback |

### §5.3 D47 — First deploy issues

| Failure | Detection | Recovery |
|---|---|---|
| `docker compose pull` rate limit (Docker Hub anonymous) | 429 / "toomanyrequests" | `docker login -u bgozlinski -p <PAT>` na VM bypassuje (200/6h) |
| `.env` SECRET_KEY z `$` | Compose warnings + Django ImproperlyConfigured | Regenerate alphanumeric per §3.7 |
| `.env` brakuje wymaganego var (np. `DJANGO_SECRET_KEY`) | Container `ImproperlyConfigured: Set the X environment variable` | Edit `.env`, `docker compose down + up -d` |
| Postgres data corruption (rare) | Migrate fails / web crashes | `docker compose down -v` + restart (data loss — fresh DB) lub manual `pg_dump` restore |
| Discord bot invalid token | `discord_bot` restart loop, `docker logs` shows "Improper token" | Regenerate token w Discord Developer Portal, edit `.env`, `docker compose up -d --no-deps discord_bot` |
| Kuma initial setup race (first user setup form skip) | UI shows login form bez option to create admin | Container restart (`docker compose restart uptime-kuma`) — Kuma re-renders setup form gdy no users w DB |

### §5.4 Rolling update failure (post-D47 ongoing ops)

| Failure | Detection | Recovery |
|---|---|---|
| New image broken (pull works, container crashes) | `docker compose ps` shows web Restarting | Pinned rollback: edit `docker-compose.yml` `image: bgozlinski/tibiantis-scraper:sha-<previous>` + `docker compose up -d` |
| Migration fail (new schema breaks rollback) | `migrate` exit 1 in logs | Operator decides: fix forward (CI new build z fix) lub manual `docker compose exec web python manage.py migrate <app> <prev-migration>` (risky, data implications) |
| `docker compose pull` slow / hang | Network issue Hetzner ↔ Docker Hub | Retry, check status.docker.com |

### §5.5 Idempotency guarantees

- **`bootstrap.sh`:** idempotent except `useradd` (fails if user exists — `set -e` exits). Operator wie z runbook'a "run on fresh VM only". M-future: dorzucić `id deploy &>/dev/null || useradd ...` patterns.
- **`docker compose pull`:** idempotent (no-op gdy image cached).
- **`docker compose up -d`:** idempotent (no-op gdy containers already running with current image; recreate gdy image changed).
- **Migrate one-shot:** idempotent (Django `migrate` no-op gdy schema up-to-date).

## §10 Otwarte pytania dla M9.5 retro

Te kandydaci mogą surface'ować podczas M9.5 implementacji (zaznacz w PROGRESS.md "Tech debt z M9.5"):

- **`bootstrap.sh` idempotency** — aktualnie `set -e` exit przy ponownym uruchomieniu (useradd duplicate). Czy to OK lub dorzucić `id deploy &>/dev/null || useradd ...` patterns? Decision w D46 PR review.
- **Hetzner Cloud Firewall vs UFW redundancy** — czy oba warto utrzymywać? Hetzner Firewall stops traffic at Hetzner edge (cheaper), UFW na host (defense if Hetzner Firewall misconfigured). Lean answer: tak, defense-in-depth.
- **`.env` file ownership/perms** — `chmod 600` jest minimum. Czy dorzucić `chown deploy:deploy` explicit? Decision w D47.
- **Image size 480MB pull przez VPS** — first pull może trwać 30-60s w Falkenstein. Czy acceptable? Tak (one-time cost, M-future split image jeśli problem).
- **Docker Hub PAT rotation policy** — PAT bez expiration = security debt. Hetzner deploy security review (M-future).
- **Kuma DB persistence** — `uptime_kuma_data` volume utrzymuje monitors config. Czy backup tego? M-future (Kuma config easy to recreate).
- **Hetzner public IPv4 ephemeral** — server destroy + recreate = new IP. M-future: reserve static IP (~1€/mc) jeśli DNS A record stabilność wymagana.
- **Docker pull rate limit hits** — anonymous 100/6h może hit w M9.5 jeśli częste recreate VM. Mitigation: `docker login` z PAT bypassuje (200/6h authenticated). M-future: cache layer (Harbor / Registry mirror).
